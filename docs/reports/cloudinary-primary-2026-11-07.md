# أولوية Cloudinary لصور المنتجات — 2026-11-07

## التصحيح

- تستخدم صور Open Graph وبيانات المنتج JSON-LD الرابط الأساسي المخزن للمنتج، مثل صور المتجر. أُزيل اختيار نسخة Supabase الاحتياطية مسبقًا.
- لا ينجح رفع صورة منتج جديدة إلا بعد حفظ النسخة الاحتياطية في Supabase ورفع النسخة الأساسية إلى Cloudinary. عند فشل Cloudinary، يعيد المسار خطأ 502 واضحًا دون رابط بديل يحفظه النموذج كمصدر دائم. يبقى الملف المختار لإعادة المحاولة، وتبقى نسخة Supabase محفوظة.
- يستمر مكوّن الصور في عرض المصدر الأساسي أولًا والتبديل إلى Supabase فقط عند فشل التحميل أو استلام صورة خطأ بحجم بكسل واحد. لا يغيّر هذا التبديل روابط قاعدة البيانات.

## النطاق والحدود

- يتطلب التصحيح نشر التطبيق؛ لا يحتاج إلى ترحيل SQL ولا تغيير الاشتراك.
- لم تُعدّل بيانات الإنتاج أو تُحذف صور أو تُنفّذ عمليات رفع أثناء التصحيح. لا يمحو النشر استهلاك نقل البيانات السابق.
- الروابط التاريخية التي تشير مباشرة إلى Supabase لا يمكن تحويلها إلى Cloudinary بتغيير اسم المضيف؛ يلزم نسخ الملف والتحقق منه أولًا. الفحص السابق وجد 11 مرجعًا من هذا النوع داخل الطلبات القديمة، بينما روابط صور المنتجات الحالية كلها Cloudinary.
- صور مراجعات العملاء لها مسار رفع مستقل إلى Supabase، لم يتغير في هذا التصحيح الخاص بصور المنتجات.
- لا يمكن إسناد كامل استهلاك Cached Egress إلى صور المشاركة دون سجلات الطلبات. هذا التصحيح يزيل استخدام الاحتياطي مسبقًا، ولا يدّعي تفسير جميع الزيارات السابقة.
- إعادة محاولة رفع فشل في Cloudinary قد تترك نسخة Supabase غير مرتبطة، مثل فشل حفظ المنتج بعد رفع الصور. لم يُضف حذف تلقائي قد يزيل أصلًا مطلوبًا.

## التحقق

تغطي اختبارات الصور تنفيذ صفحة المنتج للتحقق من رابط Open Graph وJSON-LD ومعلومات العرض، وفشل Cloudinary بعد حفظ النسخة الاحتياطية دون إعادة رابط Supabase قابل للنشر، والتبديل الاحتياطي داخل المتصفح. اتصالات الرفع في الاختبارات محاكاة، ولا تتصل بحساب الإنتاج.

- نجح `npm run test:images` و`npm run test:admin` و`npx tsc --noEmit`.
- نجح ESLint لمسار الرفع وملف اختبارات الصور، ونجح `git diff --check`.
- أظهر ESLint لصفحة المنتج 18 مخالفة `no-explicit-any` موجودة قبل التعديل؛ أعيد الفحص على نسخة `HEAD` وأظهرت المخالفات نفسها. لم تُغيّر أنواع الصفحة ضمن هذا التصحيح.
- لم يُنفّذ نشر أو اختبار رفع على الحساب الحي، ولم يُشغّل بناء الإنتاج في هذه الجولة.

## التحقق اللاحق من الكود والإنتاج — 2026-11-07

النتيجة: مسار صور المنتجات يستخدم Cloudinary أولًا، لكن تعميم ذلك على جميع صور الموقع غير صحيح حاليًا. صور المراجعات المنشورة ما زالت تُحمّل مباشرة من Supabase.

### أدلة القراءة من الإنتاج

| المصدر | النتيجة |
| --- | --- |
| `product_color_images` | 196 مرجعًا، كلها Cloudinary |
| `product_colors` | 111 مرجعًا، كلها Cloudinary |
| `order_items` | 1173 مرجع Cloudinary و11 مرجع Supabase تاريخيًا |
| المراجعات المعتمدة | 5 مراجع صور Supabase |
| HTML الصفحة الرئيسية المنشورة | 66 عنصر صورة Cloudinary، و5 صور Supabase من `review-images`، و3 صور محلية |
| صفحتا منتج منشورتان | HTTP 200، وصور العرض وOpen Graph وJSON-LD من Cloudinary، إحداهما ذات نسخة احتياطية معروفة والأخرى صورة قديمة |

صفحتا العينة:

- `https://melyima.com/products/d2debd79-f001-4bcd-a2f4-da41d5230a69`
- `https://melyima.com/products/ae915f15-6b46-42ef-9e2b-36c907800912`

صور المراجعات الخمس موجودة فعلًا كعناصر `img` في HTML الصفحة الرئيسية، بلا `loading="lazy"`. أعادت طلبات HEAD إليها HTTP 200 بالأحجام 131659 و303136 و601848 و1359231 و307946 بايت، بإجمالي **2703820 بايت (نحو 2.70 MB)**. هذا مسار تحميل مباشر من Supabase أثناء عمل Cloudinary، وليس نتيجة تشغيل بديل صور المنتجات. قد يستفيد الزائر من كاش المتصفح، لذلك لا يعني الرقم أن كل زيارة متكررة تنقل هذه الكمية مجددًا. لا تكفي هذه العينة لإسناد كامل 7.76 GB السابقة دون سجلات الطلبات.

أعادت صورتان من Cloudinary ضمن الصفحة الرئيسية HTTP 200 أيضًا. الفحص استخدم HTML وطلبات HEAD دون تنزيل ملفات الصور أو تعديل بيانات الإنتاج.

### الاختبارات والبناء

- نجحت اختبارات الصور والإدارة مجددًا.
- أضيف اختبار للنموذج الفعلي: فشل رفع Cloudinary يمنع استدعاء حفظ المنتج والانتقال من المحرر، ويحتفظ بالملف المختار؛ إعادة المحاولة الناجحة ترسل رابط Cloudinary في بيانات المنتج. نجح اختبار واجهة الإدارة وESLint لملف الاختبار بعد الإضافة.
- نجح `npm run build`، بما فيه TypeScript وتوليد 53 صفحة.
- فُحص HTML لجميع صفحات المنتجات المولّدة محليًا: **24 من 24** تستخدم Cloudinary في Open Graph وJSON-LD، دون عناصر صور Supabase داخل تلك الصفحات.

### ما لا يزال غير مكتمل

1. صور المراجعات لها مسار مستقل في `ReviewForm` و`/api/reviews`؛ يلزم جعله يرفع إلى Cloudinary مع نسخة احتياطية، وترحيل الصور الخمس الحالية بعد التحقق من النسخ، حتى يطابق الموقع كله السياسة المطلوبة. تعديل صور المشاركة وحده لا يعالج هذا المسار.
2. مراجع صور الطلبات القديمة في Supabase لم تُرحّل في هذا الفحص. السلال القديمة المحفوظة في متصفحات الزوار قد تحتفظ بروابط تاريخية أيضًا.
3. من 215 رابط Cloudinary فريدًا ضمن الجداول الثلاثة المفحوصة، يتعرف المساعد الحالي على نسخة Supabase احتياطية لـ35 فقط. لا تثبت هذه النتيجة عدم وجود ملفات احتياطية للصور الأخرى؛ تعني عدم وجود ربط يعرفه مكوّن العرض. لذلك لا يصح ضمان التحويل الاحتياطي لكل الصور القديمة.
4. تحقق الرفع والتحويل الاحتياطي اختباري بمحاكاة الاتصالات والأحداث؛ لم يُرفع ملف تجريبي إلى الإنتاج. لم تتوفر جلسة متصفح للفحص التفاعلي، لذا لا ندّعي اختبار شبكة المتصفح بعد تشغيل JavaScript أو إثبات إصدار مسار الرفع المنشور.

لم يُنفّذ نشر أو ترحيل أو حذف أو تحديث فواتير خلال هذا التحقق.
