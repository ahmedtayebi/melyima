## التنفيذ للمسؤول

من مجلد المشروع، باستخدام النسخة المحدّثة من الكود وملف `.env.local` الموجود:

```bash
npm run images:mirror -- --dry-run
npm run images:mirror -- --apply
```

نجح الفحص للقراءة فقط أثناء التطوير: **16 مرجعًا / 13 صورة Supabase فريدة** قابلة للنقل، و1480 مرجعًا آخر لا تحتاج إلى تحويل. تشمل هذه الدفعة صور المراجعات الخمس وصور الطلبات القديمة. قد يتغير العدد إذا تغيرت البيانات.

بعد نجاح `--apply` مع `0 conflicts/errors`، انشر النسخة المحدّثة على Vercel. يجب أن يأتي النشر بعد النقل حتى تُبنى صفحات المتجر بالروابط الجديدة. لا يلزم SQL أو حذف ملفات أو زر تحديث يدوي. لم يُنفّذ النقل أو النشر أثناء إعداد هذا التعديل.

عند انقطاع النقل، احتفظ بـ`.local/image-mirror/state.json` وأعد أمر `--apply` نفسه. لا تحذف السجل؛ الأداة تتحقق من النسخ الموجودة وتستأنف. لا تتجاوز رسائل التعارض، فهي تحمي التعديلات التي حدثت أثناء النقل.

## ما تغيّر

- يحتفظ رفع مراجعة جديدة بالنسخة الأصلية في `review-images` في Supabase. قبل حفظ المراجعة، يقرأ `/api/reviews` الصور من هذا المخزن فقط، يتحقق من الحجم والمحتوى، ويرفعها إلى Cloudinary بطلب موقّع ثم يحفظ روابط Cloudinary. لا تُحفظ مراجعة جديدة بصور Supabase إذا فشل Cloudinary؛ تبقى البيانات والصور المختارة لإعادة المحاولة.
- حد المراجعة ثلاث صور، وحد الصورة 5 MiB. تُرفض الروابط الخارجية والاستعلامات والمسارات غير المدعومة وإعادة التوجيه والمحتوى غير الصوري. لا ينتقل مفتاح Cloudinary إلى المتصفح. الرفع الموقّع يظل ضمن مسار إرسال المراجعات الموجود؛ لم يُنشأ مسار رفع Cloudinary عام مستقل.
- تعرض بطاقات المراجعات وصورها المكبّرة وصورها في الإدارة Cloudinary أولًا باستخدام مكوّن التحويل الاحتياطي نفسه. تستخدم بطاقات المراجعات التحميل المؤجّل أيضًا.
- أضيف الربط `melyima/supabase-v2` للصور في `review-images` و`product-images` ومسارات `catalog-images` القديمة. يحتفظ بمعرّف المشروع والمسار الأصلي المشفّر داخل معرّف Cloudinary، ليُستخرج رابط Supabase المطابق عند فشل التحميل. يبقى ربط v1 السابق متوافقًا.
- توسعت أداة `images:mirror` لتشمل مصفوفة `reviews.images` والروابط القديمة، مع الاحتفاظ بسجلها السابق. تنقل فقط الصور المشار إليها في قاعدة البيانات، وتقارن SHA-256 للنسخة الأصلية في الخدمتين قبل استبدال الرابط. النسخ الأصلية لا تُحذف.
- استبدال رابط مراجعة يقارن مصفوفة الصور الحالية كاملة قبل التحديث، فلا يكتب فوق تعديل متزامن أو إعادة ترتيب. يحفظ رقم موضع الصورة في السجل، ويعالج تكرار الصورة والاستئناف والرجوع.

## الحدود

- يبقى Supabase مصدر تنزيل النسخة الأصلية مرةً أثناء النقل أو إرسال مراجعة جديدة، ومصدر العرض عند فشل Cloudinary؛ الهدف إزالة العرض المباشر المعتاد للصور المنشورة، وليس جعل نقل Supabase صفرًا.
- الصور القديمة الموجودة أصلًا في Cloudinary دون ربط احتياطي معروف لم تُغيّر. السلال القديمة المحفوظة في متصفحات الزوار قد تحتفظ بروابط تاريخية.
- واجهة إرسال المراجعات عامة كما كانت، وهذه الجولة لا تضيف نظامًا جديدًا لمنع الرسائل الآلية أو حدودًا موزعة للطلبات. معرّفات Cloudinary ثابتة و`overwrite=false` لمنع استبدال الأصل عند إعادة المحاولة.
- قد تبقى نسخ غير مرتبطة عند فشل حفظ مراجعة بعد رفع الصور. لا توجد مهمة حذف تلقائي أو ادعاء بأن هذه الملفات خالية من المراجع.

## التحقق

- اختبارات تحويل روابط v1 وv2 واستخراج النسخة الأصلية ورفض المسارات غير الصحيحة.
- اختبارات تنزيل المراجعات: الحجم والمحتوى، الروابط الخارجية، تكرار الصورة، فشل Cloudinary قبل إدراج المراجعة، وإعادة المحاولة.
- اختبارات نقل مصفوفة الصور: الفحص دون كتابة، التحقق من النسخ، الاستئناف، الرجوع، حذف السجل، نقل الصورة لموضع آخر والتعديل المتزامن.
- اختبارات عرض النسخة الأساسية ثم النسخة الاحتياطية عند فشل التحميل لصور المراجعات والمنتجات القديمة.
- فحص TypeScript نجح. اختبارات الاتصالات تستخدم محاكاة؛ الفحص الإنتاجي الذي أُجري كان `--dry-run` فقط.
- نجحت `npm run test:images` و`npm run test:admin` و`npm run build` (53 صفحة)، وESLint للملفات المعدّلة و`git diff --check`.
